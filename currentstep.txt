Business Dashboard - Profile Management System

🎯 PROJECT OVERVIEW
We built a comprehensive business dashboard profile management system for a Yelp-like platform focused on India. Business owners can manage their complete business profile through a tabbed interface with real-time updates, image uploads, and full CRUD operations.

🏗️ ARCHITECTURE & TECH STACK
Core Technologies
Framework: Next.js 15 (App Router)

Language: TypeScript

Database: PostgreSQL with Prisma ORM

State Management: Zustand

Data Fetching: TanStack React Query v5

Form Handling: React Hook Form + Zod validation

UI Components: Custom UI components (shadcn/ui style)

Styling: Tailwind CSS

File Upload: Cloudinary

Authentication: Clerk (custom implementation with verifyBusinessAccess)

Build Tool: Turbopack

Key Patterns
Server Components for data fetching

Client Components for interactivity

Server Actions for mutations

Optimistic updates with React Query

Type-safe forms with Zod schemas

Separation of client/server utilities

🔐 AUTHENTICATION & AUTHORIZATION
lib/auth.ts - Key Functions
verifyBusinessAccess(businessId: string)

typescript
export async function verifyBusinessAccess(businessId: string) {
  const { userId } = await auth()

  if (!userId) {
    return { success: false, error: "Not authenticated" }
  }

  const business = await prisma.business.findUnique({
    where: { id: businessId, ownerId: userId }
  })

  if (!business) {
    return { success: false, error: "Business not found or access denied" }
  }

  return { success: true, business }
}
Used in ALL server actions to ensure user can only modify their own businesses.

🧪 KEY TECHNICAL DECISIONS
1. Why React Hook Form + Zod?
Type-safe forms

Automatic validation

Performance (uncontrolled inputs)

Easy integration with server actions

2. Why React Query?
Automatic cache management

Optimistic updates

Loading/error states

Refetch on focus/reconnect

Query invalidation after mutations

3. Why Zustand?
Lightweight (compared to Redux)

No Provider needed

Simple API

TypeScript support

Perfect for UI state (not data)

4. Why Split Cloudinary Utils?
Cloudinary SDK requires Node.js modules

Can't bundle in client components

Next.js webpack throws errors

Solution: server utils + client utils

5. Why Server Actions?
Type-safe server-client communication

No need for API routes (for mutations)

Progressive enhancement

Integrated with Next.js cache

6. Why Separate Components by Feature?
Easier to maintain

Clear responsibility

Easier to test

Can be reused

🚨 ERROR HANDLING PATTERNS
Server Actions
typescript
try {
  // Verify access
  const accessCheck = await verifyBusinessAccess(businessId)
  if (!accessCheck.success) {
    return { success: false, error: "Access denied" }
  }

  // Perform operation
  await prisma.business.update({ ... })

  // Revalidate
  revalidatePath("/business/dashboard")

  return { success: true, message: "Success" }
} catch (error) {
  console.error("[ACTION_NAME] Error:", error)
  return { success: false, error: "Something went wrong" }
}
